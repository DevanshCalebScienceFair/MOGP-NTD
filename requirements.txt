# Versions pinned to the mogp-drug env that this checkout is known to run on
# (Python 3.11). The loose bounds this file used to carry resolved to a stack
# that does not work here, so they are now exact.
#
#   conda env: python 3.11 + vina + openbabel + ninja + rdkit  (conda-forge)
#   everything below: pip
#
# >>> DO NOT `pip install -r requirements.txt` INTO A FRESH ENV. <<<
# It will fail with ResolutionImpossible. PyTDC 1.1.15 declares numpy<2.0 while
# the rest of the stack needs numpy 2.x, so this set cannot be produced in one
# resolver pass — it has to be installed in phases. Use the script instead:
#
#   bash setup_env.sh [env-name]
#
# This file remains the authoritative record of WHICH versions the env carries,
# and `pip install --dry-run -r requirements.txt` against the built env is a
# useful drift check. It is just not a one-shot installer.
#
# NOTE: rdkit is installed from CONDA, not pip, and is therefore absent from
# this file on purpose. The pip wheel for cp311 is compiled against NumPy 1.x
# and dies with "AttributeError: _ARRAY_API not found" under NumPy 2. Installing
# it here would silently break the env. Get it with:
#   conda install -c conda-forge rdkit
#
# WHAT EACH PIN IS FOR. Found by grepping the repo's imports; the claims about
# what a package pulls in come from the installed packages' metadata. "BO path"
# means `python loop.py` and everything it imports (mogp_core/, mogp.py,
# mogp_coregionalized.py, acquisition.py, evaluation.py, admet_oracle.py, data.py,
# docking.py, ...).
#   BO path   imported on that path
#   ADMET     only to TRAIN or re-export the ADMET forests (train_admet_oracle.py,
#             spec/admet/capture_admet.py); predicting reads mogp_core/admet_export/
#   GP-MOBO   only for the quarantined GP-MOBO comparator (baseline_gpmobo.py,
#             gpmobo_ref.py, external/GP-MOBO)
#   ORACLE    only as a differential test oracle (test_core_*.py, spec/*/capture_*.py)
#   VIEWER    only for dashboards, plots and reports
#   TESTS     only to run the test suite
# A pin can carry several tags. These comments describe the pins; they do not
# change them.
#
# PyTDC. [ADMET] train_admet_oracle.py pulls the TDC ADMET training sets with it,
# and data.pull_molecules pulls the ChEMBL sample (MolGen) for a library build.
# [BO path, import only] data.py imports tdc.generation at module scope, so
# `import loop` fails without it even though the optimizer never calls it.
PyTDC==1.1.15
# Pinned: the serialized models in models/pretrained_admet/ were saved with
# scikit-learn 1.9.0. Loading them under a different version triggers
# InconsistentVersionWarning and may silently produce invalid predictions.
# 1.9.0 requires Python >= 3.11 — this is why the env is 3.11 and not 3.10.
# [ADMET, ORACLE] NOT needed to predict: admet_oracle.py evaluates the numpy export
# in mogp_core/admet_export/. Used by train_admet_oracle.py (the
# HistGradientBoosting fit), spec/admet/capture_admet.py (reads the pickles to
# make the export) and test_core_admet.py (oracle). The pin only guards loading
# the pickles. scikit-learn is also a PyTDC dependency, so it stays installed.
scikit-learn==1.9.0
# [ADMET, ORACLE] Saves and loads the pickled models (train_admet_oracle.py,
# spec/admet/capture_admet.py, test_core_admet.py). admet_oracle.py imports it in
# a try/except only so the attribute `admet_oracle.joblib` exists for a test's
# monkeypatch; nothing calls it. Also a scikit-learn dependency.
joblib==1.5.3
# [BO path] DataFrames in loop.py, data.py, docking.py, admet_oracle.py and the
# result CSVs. Also a PyTDC and streamlit dependency.
pandas==2.3.3
# [BO path] The whole numerical core: mogp_core/ is numpy only. This pin and the

# version with any result.
