## 1. Model definition

### 1.1 Data and layout

* `N` training molecules, fingerprints `X ∈ {0,1}^{N×2048}` (Morgan, stored `int8`).
* `T = 2` **modelled** tasks, in `mogp.TASK_NAMES` order restricted to
  `mogp.DOCKING_TASK_INDICES`: `t=0` → `PfDHFR_Docking`, `t=1` → `hDHFR_Docking`.
  The three ADMET objectives are known exactly and are **not** modelled (grey box).
* Targets are **ligand efficiency**, `LE = raw_vina_kcal / heavy_atom_count`
  (`docking.raw_to_ligand_efficiency`), not raw kcal/mol.
* Per-column standardization on the training set, computed over the **full**
  `len(TASK_NAMES)` matrix and then masked: `y_mean[j]`, `y_std[j]` are `NaN` for every
  non-docking column, and `y_std == 0` is replaced by `1.0`.
  `Y_norm = (Y[:, docking] − y_mean[docking]) / y_std[docking]`, shape `(N, T)`.

Throughout, I write `K` for the number of modelled tasks when it appears in a formula
and `T` when talking about the project; they are the same number, 2.

### 1.2 Kernels

**Data kernel — Tanimoto / Jaccard, no hyperparameters at all.** For rows `x, x'`:

```
                    <x, x'>
(K1)   k(x, x') = ---------------------------- ,  clipped to [0, 1]
                  sum(x) + sum(x') − <x, x'>
```

with the denominator clamped below at `eps = 1e-8` so an all-zero fingerprint gives 0
rather than `0/0`. For binary vectors `<x,x> = sum(x)`, so `k(x,x) = 1` exactly whenever
`sum(x) > 0`. Write `K_XX ∈ R^{N×N}` for the Gram, `K_*X ∈ R^{M×N}`, `K_**`.

There is **no `ScaleKernel`** around it and no lengthscale. This matters twice:
1. `K_XX` is a *constant* of the training set. It does not change during optimization.
   Everything expensive that depends only on `K_XX` is computed once (§4).
2. All output scale is carried by `B`. In the textbook ICM, `B` and a kernel outputscale
   are only jointly identified; here that redundancy is closed, so **`B` itself is
   identified** (§7).

**Task kernel — coregionalization matrix.**

```
(B1)   B = W Wᵗ + diag(softplus(v_raw)) ,   W ∈ R^{K×R},  v_raw ∈ R^K
```

`R` is the rank (`rank=1` is the project default and the only value the loop ever
passes). `B` is symmetric and strictly positive definite because
`softplus(v_raw) > 0` elementwise.

### 1.3 Full covariance — the Kronecker product

The ICM (Bonilla, Chai & Williams 2008; Álvarez, Rosasco & Lawrence 2012, §4)
places on the vector-valued latent function `f: X → R^K` the covariance

```
(C1)   cov( f_t(x), f_s(x') ) = B[t,s] · k(x, x')
```

i.e. one shared latent process replicated across tasks with cross-task weights from `B`.
Vectorized with the **data-major** flat index `a = i·K + t` (§3), the training-set latent
covariance is exactly the Kronecker product

```
(C2)   K_f = K_XX ⊗ B        ∈ R^{NK × NK}
```

### 1.4 Mean and noise

Mean: one constant per task. `m[i·K + t] = c_t`, i.e. the mean matrix is
`1_N c^T`. `c ∈ R^K` is trainable and initializes to `0` (measured,
`fixtures/01_parameterization.json`).

Noise, as the model is fit today — **a per-task variance plus one shared global
variance**:

```
(N1)   Σ_noise = I_N ⊗ diag(τ) + σ² I_{NK} = I_N ⊗ diag(τ + σ² 1)   with
       τ_t = softplus(τ_raw,t) + 1e-4 ,   σ² = softplus(σ_raw) + 1e-4
```

Both floors are `1e-4` (measured to 0 error against the library,
`fixtures/01_parameterization.json`). Write

```
(N2)   d = τ + σ² 1  ∈ R^K_{>0}     (d_t ≥ 2e-4 always)
```

so the noise is *itself* a Kronecker product `I_N ⊗ diag(d)`. That is the single fact
that makes §4 work.

**Training covariance:**

```
(C3)   Σ = K_XX ⊗ B + I_N ⊗ diag(d)
```

### 1.5 Parameter vector

| group | shape | link to constrained value | init in the shipped model |
|---|---|---|---|
| `W` (`covar_factor`) | `(K, R)` | identity | `randn`, **redrawn every construction** |
| `v_raw` (`raw_var`) | `(K,)` | `softplus`, **no offset** | `randn`, redrawn |
| `c` (per-task constant mean) | `(K,)` | identity | `0.0` |
| `τ_raw` (`raw_task_noises`) | `(K,)` | `softplus(·) + 1e-4` | `0.0` |
| `σ_raw` (`raw_noise`) | `(1,)` | `softplus(·) + 1e-4` | `0.0` |

Count: `K·R + 3K + 1`. For `K=2, R=1` that is **9 trainable scalars** (measured, and all
9 are reached by `torch.optim.Adam(model.parameters())` because the likelihood is
registered as a submodule of the `ExactGP` — there is no missed-parameter bug).

> The charter's phrase "3T+1 trainable scalars" describes the *independent* model in
> `mogp.py`, not this one. The ICM has `K·R + 3K + 1 = 9` at `K=2, R=1`. The charter's
> substantive instruction — **one shared global `σ²` on top of per-task noises, not T
> independent GPs** — is what (N1) encodes, and it is what the shipped model does.
> The `mogp_coregionalized.py` module docstring line 34 says the likelihood gives
> "(per-task noise)"; that is incomplete, not wrong: there are per-task noises **and**
> a shared global one. Fix the docstring, keep the model.

Numerically safe helpers (needed because `raw` values reach ±13 during fitting):

```
(P1)   softplus(x) = log1p(exp(−|x|)) + max(x, 0)
(P2)   softplus'(x) = sigmoid(x) = 1/(1+exp(−x))  for x ≥ 0,  exp(x)/(1+exp(x))  otherwise
```

## 2. THE TRANSPOSE TRAP — settled empirically

**The reported risk is real and the docstring is the thing that is wrong.**

gpytorch's `MultitaskKernel` docstring describes `K_TT ⊗ K_XX`. The assembled dense
matrix is `K_XX ⊗ B`.

Experiment (`capture_icm.py::section_ordering`, fixtures `02_ordering*`): build a
`MultitaskKernel` with `N=3`, `K=2`, a *fixed* data kernel returning a hand-written
asymmetric-valued PSD matrix, and an `IndexKernel` forced to realize a hand-written `B`
whose off-diagonal differs from the data kernel's. Then compare the assembled `6×6`
dense matrix against both candidate orders.

```
K_data = [[1.0, 0.5, 0.2],      B_task = [[1.0, 0.1],
          [0.5, 1.0, 0.3],                [0.1, 4.0]]
          [0.2, 0.3, 1.0]]

max | assembled − kron(K_data, B_task) | = 4.44e-16      <-- MATCHES
max | assembled − kron(B_task, K_data) | = 3.0           <-- the docstring order, WRONG

probe entry [0,1]:  assembled 0.1 = K_data[0,0]·B[0,1] ,  not 0.5 = B[0,0]·K_data[0,1]
```

### 2.1 The index arithmetic the numpy implementation needs

**Ordering (data-major / "interleaved"):**

```
(O1)   flat index a of (molecule i, task t)  =  i·K + t          0 ≤ i < N, 0 ≤ t < K
(O2)   Σ[a, b] = Σ[i·K+t, j·K+s] = K_XX[i,j]·B[t,s] + δ_ij δ_ts d_t
```

Equivalently, with `Y ∈ R^{N×K}`, the vector `y` is `Y.reshape(-1)` — plain numpy
C-order, no transpose. Row = molecule, column = task, always.

**The reshape identity that replaces every Kronecker matvec.** For `P ∈ R^{N×N}`,
`Q ∈ R^{K×K}` and `v = V.reshape(-1)` with `V ∈ R^{N×K}`:

```
(O3)   (P ⊗ Q) v  =  (P V Qᵗ).reshape(-1)
```

Never materialize `P ⊗ Q`. Every formula in §4–§6 is written using (O3).

**The corollary nobody should skip:** the marginal likelihood is **invariant** to which
ordering you pick, because `kron(K_XX,B)` and `kron(B,K_XX)` are permutation-similar and
permuting `y` and `Σ` consistently leaves `yᵗΣ⁻¹y` and `log det Σ` unchanged. Measured:
the two manual computations agree to `0.0`. So a transpose here **cannot be caught by
the loss, the hypervolume, or any aggregate metric** — it only shows up in per-task
posterior mean/variance, where it silently swaps PfDHFR's prediction with hDHFR's.
This is why it has to be tested directly, on an asymmetric fixture, exactly as above.

**Marginal-variance reshape.** Measured with a diagonal covariance of
`[100,200,300,400,500,600]`, the per-task variance matrix comes back as
`[[100,200],[300,400],[500,600]]`, i.e.

```
(O4)   var[i, t] = diag(Σ_post)[i·K + t]
```

consistent with (O1). Independently: `acquisition.py:323` does
`torch.diag_embed(var_d.reshape(*batch, q*k))` with `var_d` of shape `(*batch, q, k)`;
the C-order flatten gives index `q_i·k + t`, which **is** (O1). That particular reshape
is *not* transposed. (Its other problem is §8.)

## 3. Exploiting the Kronecker structure

### 3.1 Simultaneous diagonalization

`Σ = K_XX ⊗ B + I_N ⊗ diag(d)` is **not** a Kronecker product, so you cannot
eigendecompose it factorwise directly. Whiten by the noise first (this is the
"Kronecker sum with structured noise" trick of Rakitsch, Lippert, Borgwardt & Stegle,
*It is all in the noise*, NIPS 2013, §2; the noiseless-`B` version is Stegle et al. 2011):

```
Σ = (I ⊗ D^{1/2}) [ K_XX ⊗ (D^{−1/2} B D^{−1/2}) + I_N ⊗ I_K ] (I ⊗ D^{1/2}),
    D = diag(d)
```

Now both terms in the bracket are Kronecker products sharing the identity, so one
eigendecomposition per factor diagonalizes it:

```
(S1)   K_XX = U diag(λ) Uᵗ                      U orthogonal, λ ≥ 0      [N×N, ONCE]
(S2)   B̃ = D^{−1/2} B D^{−1/2} = V diag(μ) Vᵗ   V orthogonal, μ > 0      [K×K, per step]
(S3)   Ṽ = D^{−1/2} V                           (NOT orthogonal)
(S4)   S[p,q] = λ_p·μ_q + 1                     (N×K, strictly ≥ 1)
```

giving the exact factorization

```
       Σ    = (U ⊗ D^{1/2}V) · diag(vec S) · (U ⊗ D^{1/2}V)ᵗ
       Σ⁻¹  = (U ⊗ Ṽ) · diag(vec S)⁻¹ · (U ⊗ Ṽ)ᵗ
```

Since `S[p,q] ≥ 1 > 0` and `d_t ≥ 2e-4 > 0`, **`Σ` is positive definite for every
admissible parameter value**. No jitter is needed, and none should be added — adding
jitter would change the model.

### 3.2 Log-determinant

`log det Σ = 2 log det(U ⊗ D^{1/2}V) + log det diag(vec S)` and `|det U| = |det V| = 1`,
so:

```
(L1)   log det Σ = N · Σ_t log d_t  +  Σ_{p,q} log(λ_p μ_q + 1)
```

Cost `O(NK)` once `λ, μ` are in hand.

### 3.3 Solve

With `R ∈ R^{N×K}` the residual matrix (`r = R.reshape(-1)`), using (O3) twice:

```
(S5)   Z  = Uᵗ R Ṽ            (N×K)
       Z̃  = Z / S             (elementwise)
       A  = U Z̃ Ṽᵗ            (N×K)   and  α = Σ⁻¹ r = A.reshape(-1)
```

Cost `O(N²K + NK²)`.

fixture (`fixtures/04_kron.json`):

|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 40 | 80 | 0.14 ms | 0.022 ms | 0.144 ms | 0.160 ms | 0.099 ms | 7.2× | 0.005 s vs 0.032 s (7.0×) |

*One run. Wall clock varies ±30% run to run on this machine; across four runs the
`warm speedup` column stayed in `7–8×` at `N=40`, `60–75×` at `N=100`, `117–138×` at
`N=290` and `184–214×` at `N=600`. Do not byte-compare these.*

**Read this honestly.** The Kronecker factorization *by itself*, at `K=2`, buys almost
nothing: compare `kron cold` against `dense, logdet+solve only` — one `eigh` of an `N×N`
matrix costs about as much as, or more than, one Cholesky of a `2N×2N` matrix
(measured `cold / dense-no-inverse` speedup `0.68×` at `N=40` and `1.24–1.79×` above
that — i.e. between a small loss and a small win, never the order of magnitude the
Kronecker story suggests). `(NK)³/3 = 8N³/3` for `K=2` is
simply not much more than a symmetric eigendecomposition's `≈9–10 N³`.

The decisive win is the **caching**: `K_XX` has no hyperparameters, so (S1) is paid once
per training set and every subsequent optimizer step costs `O(K³ + NK² + N²K)`. `N=290`
is the Grand Campaign end state (`n_init=40 + 50 iterations × batch 5`), and there a
full 200-step fit drops from 2.51 s to 0.027 s. Over a 50-iteration BO run that refits
every iteration, that is the difference between minutes and under two seconds of GP
fitting.

Implementation instruction: **cache `(λ, U)` alongside the training set, not inside the
objective function.** If (S1) is recomputed per step, the whole advantage evaporates.

## 4. Marginal likelihood and analytic gradients

### 4.1 Objective

```
(M1)   log p(y | θ) = −½ rᵗ Σ⁻¹ r − ½ log det Σ − (NK/2) log 2π ,   r = y − m
(M2)   loss(θ) = − log p(y | θ) / (N·K)
```

The `/(N·K)` is the normalization the shipped printed loss uses — verified: the
gpytorch MLL value equals `log_prob / (N·K)` to `5.4e-13`. Reproduce it so the loss
numbers stay comparable. There are **no prior terms**: the shipped model registers no
priors on any parameter (measured, `named_priors()` is empty).

### 4.2 Gradient derivation

For any scalar parameter `θ` entering only through `Σ`, the standard identity
(Rasmussen & Williams, *GPML*, eq. 5.9) gives

```
∂ log p / ∂θ = ½ αᵗ (∂Σ/∂θ) α − ½ tr(Σ⁻¹ ∂Σ/∂θ) = tr(G ∂Σ/∂θ),   G := ½(α αᵗ − Σ⁻¹)
```

`Σ` depends on `θ` only through the two Kronecker directions `K_XX ⊗ ·` and `I_N ⊗ ·`,
so every gradient is one of two contractions of `G`. Define, for symmetric `K_XX`:

```
(G1)   M_B[t,s] := Σ_{i,j} K_XX[i,j] · G[(i,t),(j,s)]          (K×K, symmetric)
(G2)   M_D[t]   := Σ_i           G[(i,t),(i,t)]                 (K,)
```

so that for any symmetric `K×K` matrix `A`:
`tr(G (K_XX ⊗ A)) = ⟨A, M_B⟩_F` and `tr(G (I_N ⊗ A)) = ⟨A, diag-part⟩`.

**Closed forms.** The `α αᵗ` half is immediate from `α_i = A[i,:]`:
`Σ_{ij} K_XX[i,j] α_i α_jᵗ = Aᵗ K_XX A`. For the `Σ⁻¹` half, substitute
`Σ⁻¹[(i,t),(j,s)] = Σ_{p,q} U[i,p] Ṽ[t,q] S[p,q]⁻¹ U[j,p] Ṽ[s,q]` and use
`Σ_{ij} K_XX[i,j] U[i,p] U[j,p] = u_pᵗ K_XX u_p = λ_p` and `Σ_i U[i,p]² = 1`:

```
(G3)   g_q := Σ_p λ_p / S[p,q]        h_q := Σ_p 1 / S[p,q]           (both length K)
(G4)   M_B = ½ ( Aᵗ K_XX A − Ṽ diag(g) Ṽᵗ )
(G5)   M_D = ½ ( colsum(A ⊙ A) − (Ṽ ⊙ Ṽ) h )
```

**Per group.** `∂B/∂W[t,r] = e_t w_rᵗ + w_r e_tᵗ` with `w_r = W[:,r]`, and
`∂B/∂v_t = e_t e_tᵗ`; `∂Σ/∂τ_t = I_N ⊗ e_t e_tᵗ`; `∂Σ/∂σ² = I_{NK}`; and
`∂m/∂c_t = 1_N ⊗ e_t`. Therefore

```
(G6)   ∂ log p / ∂W          = 2 · M_B W                            (K×R)
       ∂ log p / ∂v_raw,t    = M_B[t,t] · sigmoid(v_raw,t)
       ∂ log p / ∂τ_raw,t    = M_D[t]  · sigmoid(τ_raw,t)
       ∂ log p / ∂σ_raw      = (Σ_t M_D[t]) · sigmoid(σ_raw)
       ∂ log p / ∂c_t        = Σ_i A[i,t]         ( = colsum(A) )
       ∂ loss / ∂θ           = − (1/(N·K)) · ∂ log p / ∂θ
```

Cost: `O(N²K)` dominated by `K_XX A`, everything else `O(NK² + K³)`. No `N×N` inverse,
no `NK×NK` anything.

## 5. Posterior prediction

Let `A` be the solve (S5) of the *training* residual, and precompute
`F = K_*X U ∈ R^{M×N}`, `Ḡ = B Ṽ ∈ R^{K×K}`.

```
(R1)   mean         = 1_M cᵗ + K_*X · A · B                                  (M×K)
(R2)   var_latent   = diag(K_**) ⊗_outer diag(B) − (F⊙F) · (1/S) · (Ḡ⊙Ḡ)ᵗ    (M×K)
(R3)   var_observed = var_latent + 1_M dᵗ                                    (M×K)
(R4)   cov_latent   = K_** ⊗ B − (F ⊗ Ḡ) diag(vec S)⁻¹ (F ⊗ Ḡ)ᵗ              (MK×MK)
```

(R2) is the diagonal of (R4) written without forming it: since
`(K_*X ⊗ B)(U ⊗ Ṽ) = (K_*X U) ⊗ (B Ṽ)`, the `(i,t)`-th diagonal entry of the correction
is `Σ_{p,q} F[i,p]² Ḡ[t,q]² / S[p,q]`. For the within-point `K×K` cross-task block at
test point `i`, with `w_q = Σ_p F[i,p]²/S[p,q]`:

```
(R5)   cov_latent[i] = K_**[i,i]·B − Ḡ diag(w) Ḡᵗ                            (K×K)
```

`var_observed` is what `mogp.predict` returns (the shipped code passes the latent
posterior through the likelihood). **Note** that (R3) adds the *global* `σ²` as well as
the per-task `τ_t`, since `d = τ + σ²`.

De-normalization back to the original LE scale, per docking column `j`:
`mean_orig = mean·y_std[j] + y_mean[j]`, `var_orig = var·y_std[j]²`. Non-docking columns
stay `NaN` in the full `len(TASK_NAMES)` layout.

## 7. Identifiability — confirmed, and worse than reported

### 7.1 Mathematically

**(a) Orthogonal invariance, any rank.** For any orthogonal `Q ∈ R^{R×R}`,
`(WQ)(WQ)ᵗ = W Q Qᵗ Wᵗ = W Wᵗ`, so `W ↦ WQ` leaves `B` — and therefore the entire
likelihood and posterior — exactly unchanged. Measured: `max|B − B_{WQ}| = 4.44e-16`
for `K=3, R=2` with a random `Q` (`det Q = −1.0`), `fixtures/07_identifiability.json`.
At `R=1` this degenerates to a sign flip, `Q = ±1`.

**(b) A continuous family, even at `R=1`.** For `K=2, R=1` the parameter count is 4
(`w_1, w_2, v_1, v_2`) but `B` has only 3 free entries. Given a target `B` with
`b_{12} ≠ 0`, every `t > 0` satisfying `t² < b_{11}` and `b_{12}²/t² < b_{22}` yields

```
w_1 = t ,  w_2 = b_12/t ,  v_1 = b_11 − t² ,  v_2 = b_22 − b_12²/t²
```

with `v > 0` and the identical `B`. Measured for `B = [[1.30,0.60],[0.60,0.95]]` at
`t ∈ {0.70, 0.80, 0.90, 1.00, 1.10}`: all five give `v > 0` and rebuild `B` to
`≤ 1.11e-16` (`fixtures/07_identifiability.json`). So `W` is not identified even up to
sign, and neither is `v_raw`.

**(c) What *is* identified.** `B` is. There is no outputscale to trade against it
(§1.2), so `B` is pinned by the likelihood. The task correlation
`ρ = D_B^{−1/2} B D_B^{−1/2}` is a smooth function of `B` and is likewise identified.

### 7.2 Empirically, on REAL docking data

40 real library molecules with real Vina scores against both receptors, targets = ligand
efficiency, empirical Pearson `r = 0.9312`. Refit the shipped
`train_mogp_coregionalized` from 8 torch seeds. `fixtures/07_identifiability.json`,
`fixtures/08_task_correlation.json`:

### 7.3 The finding that matters more: the seed spread is under-convergence, and the MLE is degenerate

Driving the **reference numpy NLL** to its stationary point with the analytic gradients
of §4 (plain Adam, `lr=0.05`, 40 000 steps, float64) from 4 different inits
(`fixtures/07_identifiability.json`):

```
nll ∈ [0.871824281, 0.871838500]      spread 1.42e-05   (‖grad‖∞ ≤ 8.3e-03)
task correlation  =  1.000000000      spread 1.24e-11
det B  ≈  1.1e-10  …  1.3e-10         (B is numerically SINGULAR)
τ_PfDHFR − 1e-4  ≈  1.9e-12           (AT THE FLOOR)
σ²      − 1e-4  ≈  2.0e-10            (AT THE FLOOR)
τ_hDHFR ≈ 0.1325                      (not at the floor)
```

Independent confirmation from the torch side: the 5000-step fits land at
`corr ∈ [0.999977, 0.999993]`, `τ_0 ≈ 1.3e-4`, `σ² ≈ 1.6e-4`, i.e. the same place.

**The constrained MLE is a boundary solution with a singular `B` and perfect task
correlation.** The shipped model's "learned cross-task correlation ≈ 0.994" is not the
MLE; 200 Adam steps is acting as early-stopping regularization and that is the only

flat — `0.8756` vs `0.8718`, a `0.0037` gain in normalized NLL for a change from

variance `0.8516685` (200-step) vs `0.8447819` (converged), ratio `0.9919139`; medians

### 7.4 Conclusion to state in the test suite

* **Never** test `W`, `covar_factor`, `raw_var`, `raw_task_noises`, or any raw parameter.
  They are not identified; a correct reimplementation will disagree with the library on
  all of them, by construction.
* **Do** test `B`, and preferably the derived task correlation `ρ`.
* **But** state the optimizer and stopping rule with the target, because the ICM's `B`
  is only well-defined once you do. Two honest test forms:
  * *schedule-matched*: both sides run 200 Adam steps at `lr = 0.1` from a `randn`
    init — assert `|ρ_new − ρ_ref| ≤ 1.0e-2` (measured seed spread `9.34e-03`).
  * *MLE-matched*: both sides driven to `‖grad‖∞ < 1e-4` — assert `|ρ_new − 1.0| ≤ 1e-4`
    (measured inter-init spread `1.24e-11`). This is by far the sharper test, and it is
    the one that does not depend on reproducing an optimizer trajectory.

## 8. Pre-existing scientific gap — CONFIRMED (verify, do not fix)

`acquisition.py:275–328`, class `DockingPosteriorModel`, method `posterior`:

```python
mean_np, var_np = predict(self._model, self._likelihood,
                          self._y_mean, self._y_std, fp)   # marginals ONLY
...
covar = torch.diag_embed(var_d.reshape(*batch, q * k))     # line 323
mvn = MultitaskMultivariateNormal(mean_d, covar)
```

`mogp.predict` returns `posterior.mean` and `posterior.variance` — the **marginals**.
The joint posterior is then reassembled from those marginals with a strictly diagonal
covariance. `diag_embed` appears at exactly one line, 323 (measured;
`fixtures/09_acquisition_gap.json` stores the source window and the line number).

**What is thrown away, measured on the fitted ICM and 40 real candidates**
(`train_mogp_coregionalized`, 200 steps, `lr=0.1`, `rank=1`, torch seed 0):

| discarded structure | measured | what the acquisition sees |
|---|---|---|
| within-point cross-task correlation, latent | min 0.99424, median 0.99492, max 0.99519 | `0.0` |
| within-point cross-task correlation, observed | min 0.90737, median 0.91902, max 0.92397 | `0.0` |
| between-candidate covariance blocks, max abs | `0.31714` | `0.0` |
| between-candidate covariance blocks, median abs | `0.03798` | `0.0` |

**Precisely what this implies about the ICM-vs-independent comparison as currently run:**

1. The one thing the ICM learns and the independent model cannot — the cross-task
   coupling `B[0,1]` — is used for exactly **one** purpose: it shifts the *marginal*
   posterior mean and variance of each task through the training-data solve (R1)–(R3),
   because the tasks share `α`. It is then deleted before the acquisition sees it. The
   acquisition can never sample a *jointly* correlated PfDHFR/hDHFR draw, which is
   exactly the draw that the selectivity corner of the Pareto front depends on.
2. So the ablation is **not** "correlated posterior vs independent posterior". It is
   "correlated-shrinkage marginals vs independent marginals, both fed to an acquisition
   that assumes independence". Any measured ICM advantage is attributable only to
   borrowed strength in the marginals, and the mechanism the module docstring advertises
   — "the *selective* corner of the Pareto front is hard to reach with an independent
   model" — is not actually exercised.
3. The q-batch structure is lost too (the between-candidate blocks above). qEHVI's batch
   diversity comes from the joint posterior over the `q` candidates; with a diagonal
   covariance the `q` points are sampled independently, which systematically
   under-penalizes picking `q` near-duplicates. This hits *both* arms equally, so it
   does not bias the ICM-vs-independent comparison, but it does weaken the batch
   acquisition in absolute terms.
4. It is therefore **wrong to report** the ICM arm as demonstrating that a
   coregionalized posterior helps qEHVI. What it can honestly demonstrate is that a
   coregionalized *model* produces better marginals. The numpy rewrite is the natural
   place to close this — (R4)/(R5) give the full joint covariance at the same asymptotic
   cost as the marginals — but that is a **deliberate scientific change**, not a port,
   and it must be stated and measured as one. Per the charter, this section verifies;
   it does not fix.

## 9. Library deviations, and what to do about each

**D1 — `MultitaskKernel` docstring says `K_TT ⊗ K_XX`; the code builds `K_XX ⊗ B`.**
Measured discrepancy `3.0` on the §2 fixture. *Follow the code's ordering* — not because
it is the library's, but because the data are laid out data-major everywhere in this repo
(`Y` is `(N, K)`, `acquisition.py:323` flattens `(q,k)` C-order) and (O1) is the only
ordering consistent with that. Document it as (O1)–(O4) and test it with the asymmetric
fixture. The docstring is simply wrong; it is not a specification.

**D2 — `mogp_coregionalized.MOGPCoregionalized.task_covariance_matrix` docstring says
`B Bᵗ + diag(v)`, using `B` for the factor.** The actual formula is
`W Wᵗ + diag(softplus(v_raw))`; the docstring omits the `softplus` and overloads the
name `B` for both the factor and the result. Cosmetic, but it will mislead an
implementer who reads only the docstring. *Follow the math (B1).*

**D3 — `kernel.TanimotoKernel.forward` hard-casts both inputs to `float32`**
(`x1.to(torch.float32)`), regardless of the model's dtype. A float64 gpytorch model built
on it raises `RuntimeError: expected m1 and m2 to have the same dtype`. This is why
`capture_icm.py`'s posterior oracle uses a dtype-preserving twin. *In numpy: compute the
Gram in float64 and cast once, or stay in float32 throughout.* Measured cost of the
choice: the float32 and float64 Grams differ by at most `2.29e-08`, which propagates to
`1.26e-07` relative on the posterior mean. The charter's "float32 for the GP layer"
decision is compatible with either; just be explicit.

**D4 — `mogp_coregionalized.py` line 34 documents the likelihood as "(per-task noise)".**
It is per-task noise **plus** one shared global variance (N1), 3 noise scalars for
`K=2`, not 2. *Fix the docstring, keep the model* (charter).

**D5 — the `1e-4` noise floors are undocumented gpytorch constraint defaults**
(`GreaterThan(1e-4)` on both `raw_task_noises` and `raw_noise`, transform
`softplus(x) + 1e-4`), while `raw_var` uses `Positive()` = plain `softplus` with **no**
offset. Measured to 0 error. These are arbitrary library choices, but §7.3 shows the MLE
sits **on** them: without the floors, `τ_PfDHFR` and `σ²` run to 0, `Σ` becomes singular,
and `_ref_prepare`'s `1/sqrt(d)` divides by zero. *Follow the library here, and say so
explicitly in the code*: the floor is load-bearing numerical protection, not a quirk to
be cleaned away. (A principled alternative — a weak prior on the noise — would change
the fit and is out of scope.)

**D6 — `predict_coregionalized` duplicates `mogp.predict` bit for bit** and is called
only from a test. *Do not port it.* Write one predict.

**D7 — the loss is normalized by `N·K`, not by `N`, and there are no priors.** Both are
gpytorch conventions rather than mathematical necessities, and the printed loss is
otherwise uninterpretable. *Follow the library* so loss numbers remain comparable to the
archive, and document (M2).

**D8 — `rank=2` is entirely redundant at `K=2`.** `W Wᵗ + diag(v)` with `R=1` already
spans every strictly-PD `2×2` matrix (§7.1b), so `rank` above 1 adds only
non-identifiable parameters. Measured over 8 torch seeds at 200 steps
(`fixtures/07_identifiability.json:rank_redundancy_K2`): rank-1 loss
`0.8751160–0.8773988` (mean `0.8762799`) vs rank-2 `0.8751184–0.8773195`
(mean `0.8758563`) for 2 extra parameters — indistinguishable, and the ranges overlap
almost completely. *Keep the `rank` argument for `K>2`, default 1, and document that
`R ≥ K` is pure over-parameterization.*

## 10. Edge cases and implementation warnings

1. **Clamp `λ` at 0 after `eigh(K_XX)`.** Tanimoto is PSD but *exactly* singular when
   two molecules share a fingerprint — which happens in a real library after
   densification produces near-duplicates. LAPACK then returns small negative
   eigenvalues, `S = λμ+1` can drop below 1, and `log(S)` can go `nan`. On the `N=40`
   real fixture the minimum eigenvalue is `+0.2991` and no clamping was needed, but that
   is one fixture, not a guarantee. Clamp `μ` at 0 too.
2. **Never clamp `d`.** `d_t ≥ 2e-4` by construction from the two `1e-4` floors. If you
   find yourself needing to clamp `d`, you have dropped a floor (D5).
3. **Never add jitter to `Σ`.** §3.1 proves it is already PD. Jitter would silently
   change the model and the loss.
4. **`k(x,x) = 1` exactly for binary fingerprints**, so `diag(Σ) = B[t,t] + d_t`. This
   means `B[t,t]`, `τ_t` and `σ²` are only *jointly* identified through the off-diagonal
   structure — which is why `B00` and `B11` scatter 3–4× more across seeds than `B01`
   does (measured: `B00` spread `2.01e-02` vs `B01` spread `5.67e-03` at 200 steps).
   Test `B01` and `ρ` more tightly than `B`'s diagonal.
5. **An all-zero fingerprint gives `k(x, ·) = 0` and `k(x,x) = 0`**, so that row of
   `K_XX` is zero. The model is still well-posed (noise carries it), but the posterior
   variance at such a point is `0·B[t,t] − 0 + d_t = d_t`, i.e. pure noise. Do not
   special-case it; do not let the `eps = 1e-8` clamp turn into a `1e8` blow-up (it
   cannot, since the numerator is also 0).
6. **`eigh` eigenvector signs are arbitrary and LAPACK-version dependent.** `U` and `V`
   are *not* reproducible across platforms; `logdet`, the solve, the posterior and the
   gradients are (all are invariant to column sign flips). Never write `U` or `V` to a
   fixture, never compare them, never test them.
7. **Do not transpose `Ṽ` by accident.** `Ṽ = D^{−1/2} V` scales the *rows* of `V`
   (i.e. `inv[:, None] * V`), because `D` acts on the task index which is `V`'s row
   index. `V * inv[None, :]` is a different and wrong matrix; it will still produce a
   symmetric `M_B` and a plausible-looking loss, and it will be wrong. This is the
   second silent transpose in this module and it has no library docstring to blame.
8. **The `eps = 1e-8` in the Tanimoto denominator is a `clamp(min=eps)` on the union,
   not an additive `+eps`.** For real fingerprints `union == intersection` for identical
   rows so `k = 1.0` exactly; an additive epsilon would give `0.99999999` and break the
   `k(x,x) = 1` invariant.
9. **Standardization stats come from the FULL `len(TASK_NAMES)` matrix and are then
   masked to `NaN` off the docking columns.** Predictions are scattered back into the
   full 5-column layout with `NaN` for ADMET. Preserve this contract exactly —
   `acquisition.py` and `loop.py` both index by `DOCKING_TASK_INDICES` into a 5-wide
   array.
10. **`y_std == 0` → `1.0`, not a division by zero.** Reachable in real runs: the first
    BO iteration can dock `n_init` molecules and get identical scores on one target.
11. **`softplus` must be the overflow-safe form (P1).** At the MLE, `τ_raw` reaches
    about `−13` and during fitting raw values reach `±13`; `np.log(1+np.exp(x))`
    overflows to `inf` for `x > 709` and, more insidiously, returns exactly `0.0` for
    `x < −745`, losing the gradient. (P1) is correct on both tails.
12. **Do not attempt bit-comparability with the archive.** It is float32 Adam with a
    `randn` init off a shared global RNG. §7 shows the *fit itself* is only defined to
    `~1e-2` in `ρ` at the shipped schedule.
13. **Cache `(λ, U)` with the training set** (§3.4). This is the entire performance
    argument; recomputing it per step throws away a 100×.

  semidefiniteness on binary vectors: L. Ralaivola, S. J. Swamidass, H. Saigo,
  P. Baldi, *Graph kernels for chemical informatics*, Neural Networks 18(8), 2005, §4.
* **First-principles derivations done here, not taken from any source:** the closed forms

  give the logdet/solve but not the gradient contractions in this basis); the

## 13. Unresolved

1. **Which fit is the scientific target?** §7.3 shows the shipped 200-step fit and the
   MLE are different models (`ρ = 0.994, σ² = 0.0155` vs `ρ = 1.000000, σ² = 0.0001`).
   Reproducing the archive's *behaviour* means reproducing an optimizer trajectory, which
   contradicts "derive from the mathematics". Reproducing the *mathematics* means
   accepting a degenerate boundary MLE with a singular `B`. Settling this needs a
   decision from the user, not more measurement. The cheapest principled fix — a weak
   prior/penalty on `σ²` that keeps the optimum interior — is a deliberate model change
   the charter did not authorize.
2. **Whether the boundary MLE is a real problem at campaign scale.** All of §7.3 is at
   `N=40` (the `n_init` state, i.e. the first BO iteration). At `N=200` the 200-step fit
   is already much tighter (loss spread `2.92e-04`, `ρ` spread `3.50e-03`). Whether the
   MLE stays on the noise floor at `N=290` was **not** measured; it needs a 40 000-step
   float64 run at `N=290`.
3. **Cross-platform bitwise reproducibility of the torch-fit fixtures.** On this machine,
   `07/08/09_*.json` reproduced byte-identically across two fresh interpreters, so CPU
   float32 Adam is deterministic here given `torch.manual_seed`. I cannot promise that
   across BLAS builds or architectures, so they stay flagged `stochastic`. All 30
   deterministic fixtures **were** verified byte-identical across two fresh interpreters.
4. **The complexity claim at larger `K`.** Everything measured here is `K=2`. The
   Kronecker advantage should grow with `K` (dense is `(NK)³`, Kronecker is
   `N³` once plus `O(N²K)` per step), but this was not measured beyond `K=2` because the
   project has exactly 2 modelled tasks.
5. **Rank > 1 behaviour on real data at higher `K`.** D8's redundancy argument is
   specific to `K=2`. For `K > 2`, `R < K` is a genuine low-rank restriction and the
   orthogonal non-identifiability is `R(R−1)/2`-dimensional; untested here.
